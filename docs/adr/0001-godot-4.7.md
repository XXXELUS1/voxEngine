# ADR-0001: Godot 4.7 как движок

- Статус: принято
- Дата: 2026-10-16

## Контекст

Диздок фиксирует «Движок Godot 4, физика Jolt», студия Overbrewed уже делает на нём Hellterns. Нужен
движок, в котором: (а) воксельное ядро можно подключить нативно без форка движка, (б) логика игры пишется
быстро на скриптах, (в) владелец без компилятора может открыть проект, покрутить сцену и сделать
скриншот, (г) есть ретаргетинг анимаций, активный рэгдолл и сетевой слой «из коробки».

Альтернативы: Unity (лицензия, C#-only для натива через плагины), Unreal (тяжёлый пайплайн, C++ без
удобного скриптового слоя для владельца), собственный движок (не окупится).

## Решение

Godot **4.7.2 stable**, обычная сборка (не .NET). Фиксируем:

- версия закреплена в `scripts/install_godot.sh`, в `.github/workflows/ci.yml` (`GODOT_VERSION`), в
  `godot/addons/voxbody/voxbody.gdextension` (`compatibility_minimum = "4.7"`) и в `api_version "4.7"`
  в `src/voxbody/SConstruct`;
- рендер **Forward+** (AgX, SSAO, MSAA) для игры; **Compatibility (opengl3)** используется только для
  скриншотов без GPU (`scripts/screenshot.sh`, Xvfb + llvmpipe) — поэтому шейдер вокселей обязан
  компилироваться в обоих рендерах;
- физика **Jolt** (`3d/physics_engine="Jolt Physics"` в `godot/project.godot`);
- нативный код — GDExtension (см. ADR-0003), логика — GDScript со статической типизацией.

## Последствия

- Обновление мажорной/минорной версии Godot — отдельный ADR и правка всех четырёх мест выше разом.
- Headless-режим (`godot --headless`) — основной способ проверки для Claude: импорт проекта, тесты,
  `--check-only` скриптов. Всё, что нельзя проверить без экрана, проверяется скриншотом через Xvfb.
- Владелец получает `.dll` из артефакта CI `voxbody-windows`, а не собирает сам.
- Возможности, которых в 4.7 нет (например, нативные воксели), не ждём — делаем сами (ADR-0002).
