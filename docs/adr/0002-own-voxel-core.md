# ADR-0002: Собственное воксельное ядро вместо godot_voxel

- Статус: принято
- Дата: 2026-10-16

## Контекст

Для Godot существует зрелый модуль `godot_voxel` (Zylann): террейны, LOD, стриминг, бесконечные миры,
плавные и блочные меши, свой редактор. Наши требования другие:

- тела — **маленькие плотные блоки на костях скелета** (голова 48³, кисть, туловище), которые двигаются
  целиком вместе с костью; ландшафтные механизмы (чанки, LOD, стриминг) не нужны;
- **медицинские слои**: в каждом вокселе материал (кожа, жир, мышца, кость, зуб, хрящ, сосуд, волос) и
  состояние (синяк, ожог, порез, кровь, мокрое) — три байта, а не один «тип блока»;
- **операции повреждений**: капсульный срез с пометкой раны, синяк/ожог уровнями, стрижка волос по
  высоте столбика, отваливание несвязных кусков в отдельные тела;
- **детерминизм** операций для сети (ADR-0005) и крошечная кодовая база, которую один агент держит
  в голове целиком и может перенести в следующий проект (Underfoot).

Подгонять террейновый движок под это — значит бороться с чужой архитектурой ради 5 % её возможностей.

## Решение

Своё ядро `voxbody` из пяти классов (`docs/spec/voxbody-api.md`): `VoxelVolume` (поля + операции),
`VoxelModel` (загрузка `.vxm`), `VoxelMesher` (greedy meshing + AO + тинт состояний), `VoxelPart`
(узел части, local ↔ voxel), `VoxelModelNode` (сборка модели). Коллизии — не по вокселям, а по капсулам
на костях (рэгдолл); воксели только для тел, всё остальное — обычные меши и текстуры.

## Последствия

- Мешер, AO, рейкаст, flood fill — наши; держим их простыми и покрытыми headless-тестами.
- Нет LOD и стриминга: далёких NPC с воксельными головами ограничиваем количеством, а не детализацией.
- Производительность обеспечивается правилом «перестраивать только грязную часть» и бюджетом
  ~5 мс на 48³ в release.
- Если понадобится ландшафт (Underfoot: тоннели) — это отдельное решение; ядро тел не растягиваем.
