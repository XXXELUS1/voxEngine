# Формат `.vxm` v2 — скелет, веса, пространства частей

Обратно совместим с v1 (`docs/spec/vxm-format.md`): `"format": 2`, новые ключи необязательны.
Загрузчик v2 обязан читать файлы v1. Бинарная раскладка та же: magic `VXM1`, header JSON, сырые поля.

## Пространство части: `part.space`

| значение | смысл |
|---|---|
| `"bone:<Name>"` | (как v1 `part.bone`) часть жёстко привязана к кости: `origin` в локальном пространстве кости, двигается целиком |
| `"rest"` | часть лежит в **пространстве покоя модели** (скелет в rest-позе); деформируется скиннингом по весам вокселей |
| `"world"` | пропс без скелета (как v1 без `bone`) |

Пространство покоя модели: метры, начало координат между стопами на полу, персонаж стоит в **T-позе**,
смотрит в −Z, руки вдоль ±X. Голова при 5 мм и тело при 10 мм — это две части `space: "rest"`
с разным `voxel_size`; они пересекаются по шее (перекрытие 2–3 см, оба объёма содержат воксели шеи;
мешер отбрасывает грани части, которые лежат строго внутри другой части той же модели — см. `skinned-body.md`).

## Скелет: `header.skeleton`

```json
"skeleton": {
  "profile": "humanoid",
  "bones": [
    {"name": "Hips", "parent": -1, "rest_pos": [0, 0.95, 0], "rest_rot": [0, 0, 0, 1],
     "length": 0.10, "physics": {"shape": "capsule", "radius": 0.11, "height": 0.20, "offset": [0,0.05,0]}},
    {"name": "Spine", "parent": 0, "rest_pos": [0, 0.10, 0], "rest_rot": [0,0,0,1], "length": 0.12}
  ]
}
```

- `profile`: `humanoid` | `quadruped` | `bird` | `custom`. Для `humanoid` имена костей — строго из
  `SkeletonProfileHumanoid` Godot: `Root, Hips, Spine, Chest, UpperChest, Neck, Head, Jaw, LeftEye, RightEye,
  LeftShoulder, LeftUpperArm, LeftLowerArm, LeftHand, LeftUpperLeg, LeftLowerLeg, LeftFoot, LeftToes` и
  правые; пальцы (`LeftThumbMetacarpal` …) опциональны. Так ретаргет клипов Mixamo через `BoneMap` работает без ручной карты.
- `rest_pos`, `rest_rot` — **локально к родителю** (как `Skeleton3D.set_bone_rest`). Кватернион `[x,y,z,w]`.
- `length` — длина кости в метрах (для отладки и капсул). `physics` — капсула рэгдолла/попадания в локальном
  пространстве кости (ось капсулы — вдоль Y кости, `offset` сдвигает центр); генератор считает её из мяса.
- Порядок костей: родитель всегда раньше ребёнка (индексы весов ссылаются на этот массив).

## Веса вокселей: поля `bone0`, `bone1`, `w0`

Только для частей `space: "rest"`. Три поля `uint8` в `part.fields`:

| поле | смысл |
|---|---|
| `bone0` | индекс главной кости (0..254; 255 = нет) |
| `bone1` | индекс второй кости (255 = нет) |
| `w0` | вес главной кости × 255; вес второй = 255 − w0 |

Двух костей на воксель достаточно: внутри сегмента w0 = 255, на суставе плавный переход
(`human-builder.md`, раздел «веса»). Воксель воздуха: все три поля 0 (игнорируются). При удалении вокселей
веса остаются в массиве (как и цвет) — они нужны отвалившимся кускам, чтобы знать, к какой кости относились.

## Отвалившийся кусок

`detach_disconnected` у части `rest` возвращает куски с `space: "world"` и `origin` в пространстве покоя;
рантайм ставит кусок в мир по текущему трансформу **главной кости большинства его вокселей**
(`skinned-body.md`). Веса в куске сохраняются, но не используются.

## Прочее

- `header.meta.rest_pose`: `"t-pose"` (по умолчанию) | `"a-pose"`.
- `header.height_m` — рост модели (метры), для авто-масштаба камеры и проверок.
- `header.landmarks`: словарь имя → точка в пространстве покоя (`"chin"`, `"nose_tip"`, `"left_ear"`…), необязателен;
  используется стендом стилей и инструментами для прицеливания камеры.
- `materials` и `state` — без изменений (v1).
